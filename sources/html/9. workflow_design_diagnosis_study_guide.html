💡 The Big Idea

A good AI result does not prove that AI should own the whole workflow. A bad result does not prove AI cannot do the task. You must inspect the structure underneath the result: which step is being done, what an error costs, whether it can be undone, who is accountable, and when a failure first appeared.

Core mental model: judge each workflow step, not AI as a whole.

1️⃣ Design the Work Before Placing AI

Concept 1: The unit of value is the step

A step is one named piece of a workflow with one owner. “I use AI” is a personal habit. “Our workflow uses AI” means AI performs specific named steps repeatably for the team.

Example: Instead of “AI helps with customer complaints,” map: retrieve complaint → summarize → classify severity → draft reply → approve → send.

Concept 2: Turn messy requests into requirements

A vague request is dangerous because AI fills missing details with plausible defaults. A task definition settles five things:

What?What exactly is produced?
For whom?Who receives or uses it?
How often?Once, daily, weekly?
From what data?Which sources?
What format?Table, email, dashboard?

Exam trap: A summary tells you what a document says. Requirement extraction creates specific, traceable, testable items that people can work from. Ambiguity should become a clarifying question, not an AI guess.

Concept 3: If a number matters, compute it

Synthesis means combining information into useful options. AI is good at this. But important calculations should use code execution, where code actually calculates the result. A generated number and a calculated number may look identical on screen, so use computation when the number affects a decision.

Exam rule: If a result matters, compute it. Never merely write it. Then verify the code used the correct data.

Concept 4: The Window Test

Ask: “Can I put everything this step needs in front of the model?” The model's context is everything it can see: prompt, files, conversation and available sources. If a decision depends on hidden information such as an unrecorded hiring freeze, personal relationship context, or inaccessible risk appetite, the step should stay human.

Synthesis step: inputs can be supplied. Judgment step: important inputs cannot or should not be supplied. For current prices, dates, or news, use an external source you can verify.

2️⃣ Build a Delegation Map

A delegation map writes the workflow step by step, assigns an owner to every step, and records why.

First: Eligibility → Ownership → Implementation

DecisionQuestion
EligibilityMay this data enter the AI tool, and can all required inputs be supplied?
OwnershipShould AI, a human, or both own this step?
ImplementationWhat carries the step: Skill, knowledge, code execution, standing instruction, or human gate?

Concept 5: Three ownership criteria

↩️ ReversibilityCan the action be undone? A draft can be rewritten. A sent message may be irreversible.
⚠️ StakesWhat does a mistake cost in the bad case? Think worst meaningful consequence, not average consequence.
👤 AccountabilityIs this step the actual decision someone answers for, or merely an input a person judges later? Accountability never transfers to the machine.

The three are questions, not a score. If they disagree, the strictest criterion wins.

Three classifications

ClassMeaningEasy example
🤖 AI-appropriateAI may own the step.Extract clauses for later review.
🤝 CollaborativeAI produces; a named human judges.AI drafts a contract redline, lawyer approves.
🧑 Human-retainedA person owns the step outright.Sign and send a binding contract.

Concept 6: Same criteria work across different workflows

Contract review and employee onboarding look different, but the pattern repeats. Reversible drafting and extraction can often go to AI. Final approvals, binding sends, and accountable decisions usually remain human.

Concept 7: Three common mapping failures

🚨 Over-delegationAI gets more authority than the risk of that step allows.
✨ Halo delegationAI did the previous step well, so people wrongly assume it should own the next step too.
🚪 Unstaffed gateA workflow says “human review,” but in practice nobody truly reviews it.
🛠 Tool-first mappingThe workflow is bent around a favorite feature instead of mapping the real work first.

Critical idea: good drafting is evidence about drafting. It is not evidence that AI should make the decision.

Concept 8: Maps need an owner and a review date

Workflows change silently. A map owner is one named person responsible for keeping the map true. A scheduled read is a fixed review of the map. Quarterly is a reasonable default in the course, sooner when volume, staffing, or legal conditions change.

Review: Were steps added/removed? Are collaborative gates actually staffed? Did volume or stakes change? Are Skills, knowledge, and standing instructions still current?

3️⃣ Build It, Then Watch It

Concept 9: The build loop

💭 Ideate
🧪 Prototype
💬 Feedback
✨ Refine

AI is a design partner, not a vending machine. Build something concrete, inspect it, learn what is wrong, refine it, then repeat. Keep the work inside a stable Project when background and instructions need to remain consistent.

Important distinction: if the problem is descriptive, better instructions may solve it. If the problem is a feature mismatch, such as important arithmetic being generated as prose, more wording will not fix the underlying issue.

Concept 10: Know when prompt-and-iterate is no longer enough

Escalation signal means other people now depend on your small AI tool. At that point it is becoming infrastructure and may need engineering concerns such as access control, reliability, support, and stable behavior.

SignalMeaning
Other people depend on itEscalate toward developer/architect engineering.
You solved the same shape the same way repeatedlyThe method may be stable enough to turn into a repeatable worker.

4️⃣ Diagnose Bad Output by Timing

Concept 11: Four major causes

When did it go wrong?Likely first hypothesisSimple meaning
Wrong from the first answerUnder-specificationThe prompt did not contain what the task needed.
Started well, then degradedContext overloadThe conversation became too long and early instructions lost force.
Same repeatable error typeWrong feature/modelThe task went to the wrong tool or capability.
Used to work, now doesn'tStale configurationInstructions, knowledge, or a Skill became outdated.

Timing gives you a first hypothesis, not absolute proof. Confirm cheaply before fixing.

Concept 12: Diagnostic sequence, cheapest first

  1. Check the prompt: role, context, task, constraints, format.
  2. Check session length and context overload.
  3. Check feature and model choice.
  4. Check whether configuration is current.
  5. Only then ask whether the task itself is a bad fit.
Expectation mismatch = asking the tool for something it cannot reliably provide, such as one exact future sales number. Reshape the task instead of endlessly tuning the prompt.

5️⃣ Make the Fix Stick

Concept 13: Turn reactions into instructions

“Too generic” is a reaction. “Name the audience and the single action they should take” is an instruction. Ask: What must be present for this to be right, and which part of the setup controls it?

Concept 14: Rule, Reference, or Procedure

TypeMeaningCorrect home
📏 RuleA limit or behavior that always appliesStanding instruction
📚 ReferenceMaterial the work must readKnowledge base
🧭 ProcedureAn ordered sequence of stepsSkill

Promotion means moving a useful fix out of a temporary chat and into shared configuration so it lasts.

Concept 15: Find friction

Friction is a small repeated workflow cost you stopped noticing.

SignalWhat it looks like
RepetitionYou paste the same background every run.
CorrectionYou repair the same flaw every time.
VarianceDifferent people get inconsistent outputs for the same task.

Consolidate first by combining steps that need the same background. Then promote stable repeated patterns into configuration.

Concept 16: Measure what matters

A baseline is the measurement taken before changing the workflow. Record time per run, revision rounds, and manual steps. Choose the metric that matches the purpose: time, consistency, accuracy, or variance.

A parallel run means running old and new workflows together for a few cycles. It gives evidence, a fallback, and confidence before switching fully.

6️⃣ Operate It and Explain It

Concept 17: When a bad output escapes

Design the response before the incident:

  1. Stop the workflow quickly.
  2. Scope how many outputs were affected and where they went.
  3. Tell the right people within the required time.
  4. Change the map so the lesson becomes a lasting design change.

Concept 18: Say what AI does, then name the human gate

Do not exaggerate with phrases like “fully automated,” “AI handles everything,” or “as good as a person.” State the AI's exact job and then the human checkpoint. When trust matters, also state what the workflow refuses or escalates.

A clear human checkpoint usually increases trust because people can see where accountability lives.

🛠️ Practical Work

The official course includes hands-on work. For exam preparation, do these in order:

  1. Choose one real workflow with about 5–6 steps.
  2. Map it: mark each step AI, Collaborative, or Human and justify it using reversibility, stakes, or accountability.
  3. Place the implementation: Skill, knowledge base, code execution, standing instruction, or named human gate.
  4. Run one mechanical AI step on real input.
  5. Break it deliberately: ask for an important figure in prose that should have been computed, then diagnose the failure.
  6. Promote one fix: decide whether it is a rule, reference, or procedure and place it in the right home.
  7. Record a baseline: time, revision rounds, manual steps, and your main success metric.
  8. Complete the delegation map: add a map owner, next review date, human gates, and stop/scope/tell/change incident plan.
  9. Explain the workflow three ways: to a technical colleague, an executive, and a risk/compliance person. Keep the human checkpoint in all three.

🎯 What You Must Remember

  • Judge steps, not impressive or disappointing outputs.
  • Ownership uses reversibility + stakes + accountability.
  • If all required inputs cannot enter the model's window, keep that judgment human.
  • Important numbers should be computed, not merely generated in prose.
  • Diagnose by when the symptom appeared, then check cheapest causes first.
  • Persistent fix: rule → standing instruction, reference → knowledge base, procedure → Skill.
  • Measure a baseline before redesign.
  • A collaborative step needs a real, named human gate.
  • When others depend on the tool, treat that as an escalation signal.
  • Explain AI honestly: say what it does, then name the human checkpoint.
